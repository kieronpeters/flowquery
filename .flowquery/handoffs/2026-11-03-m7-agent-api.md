## The isolation guarantee, stated precisely

**The agent namespace has no board parameter.** Not in a path, not in a body, not in a query. `boardId` is read from the credential row and nowhere else. There is no code path that could trust a client-supplied board id, because no such input exists.

Tested against a second board and a second token: read, update, move, delete and comment all return `404`, and the task is verified unchanged afterwards.

## Verification recorded

142 tests. Token plaintext never appears in a list response; revocation takes effect immediately; a cookie is rejected on `/agent` and a bearer token on the human routes; missing, malformed, unknown and revoked tokens all return the same `401`.

## Notes

- PowerShell's `Invoke-RestMethod` mangles a manually set `Cookie` header. Use `curl.exe` when testing by hand; this is a shell quirk, not an application issue.
- Activity and `last_used_at` writes are best-effort and never fail the request they describe.
