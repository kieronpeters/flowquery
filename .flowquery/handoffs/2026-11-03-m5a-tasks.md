## Decisions made here

- **One drawer for create and edit.** Two components would drift; one cannot.
- **A status change is status + position together**, computed in the service. A position is never left pointing into a column the task no longer occupies.
- **`expectedVersion` shipped now rather than in M5b**, because it is one `WHERE` clause and prevents silent clobbering from day one.
- **Task validation lives in the service**, so the API and any future agent endpoint share it.
- **The session gate was extracted** into middleware once a second router needed it.
