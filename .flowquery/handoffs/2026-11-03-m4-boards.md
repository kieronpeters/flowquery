## Test approach worth keeping

Two tiers, deliberately:

1. **Route tests with a hand-written D1 stand-in** prove HTTP behaviour quickly.
2. **`node:sqlite` + the real migration files** prove SQL behaviour — cascades, constraints, uniqueness. Anything destructive or isolation-related belongs in this tier.

Do not extend the fake to "support" a cascade; that would only test the fake.

## Design decisions made here

- **`confirmName` alone is the delete confirmation.** The earlier draft also required `confirm: true`, which carried no information. The API doc was updated to match.
- **Delete validation lives in the service**, so the UI cannot bypass it; the worst a UI bug can do is produce a `409`.
- **A ref guard, not state, prevents double submission** — two clicks in one frame both see stale state.
